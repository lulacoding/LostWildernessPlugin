═══ FEATURES ═══

🎮 **CORE PARTY SYSTEM**
• Create parties with custom names: `/party create [name]`
• Invite players: `/party invite <player>` (auto-creates party if needed)
• Accept invites: `/party accept <player>`
• Leave party: `/party leave`
• Disband party: `/party disband` (leader only)
• Kick members: `/party kick <player>` (leader only)
• View party info: `/party info`
• Max party size: 6 players (configurable)

🌐 **CROSS-SERVER SUPPORT**
• Parties persist when using portals (Survival ↔ Amplified)
• Session-based: stay in party through server transfers
• Auto-leave on full disconnect
• Database-backed state (MySQL/H2)
• Real-time sync via cluster messaging (5s polling fallback)

✨ **VISUAL DISPLAY**
• [Party] prefix in chat/tab list (colored by party)
• Party members glow to each other (configurable)
• Scoreboard team integration (no conflicts)
• Default party color: #00FF00 (green)

⚔️ **COMBAT MECHANICS**
• Friendly fire DISABLED between party members
• Party damage buff: 5% per additional member
  - 2 members = 1.05x damage (5% boost)
  - 6 members = 1.25x damage (25% boost)
• Affects direct attacks AND projectiles
• All features config-controlled

═══ PARTY PART 1 ═══

🎯 **BOSS INTEGRATION**
• Boss kill credit shared with all party members within 64 blocks
• Applies to: Withers, Devoiders, El Diablo
• Achievements unlock for entire party
• Clan boss kills increment for all party clans

🚪 **PORTAL INTEGRATION**
• Party members notified when someone uses a portal
• Formatted message: "<Player> is using a portal to <Server>!"
• No auto-teleport (players choose to follow)

🌩️ **EVENT INTEGRATION**
• Party-wide event buffs (all members receive effects)
• Event party requirements (e.g., "3+ players in parties")
• Configurable per-event

📜 **PROGRESSION INTEGRATION**
• Shared achievements: unlock for entire party
• Shared quest objectives: members contribute to leader's quest
• Party leader's counter increments when any member contributes

═══ PARTY PART 2 ═══

📊 **TECHNICAL DETAILS**

**Database Tables** (3):
• `party` - Party metadata (id, leader, name, color, max_size, created_at)
• `party_member` - Party membership (party_id, player_uuid, joined_at)
• `party_invite` - Pending invites (party_id, player_uuid, invited_at)

**Architecture**:
• Async DB operations via CompletableFuture (10s timeout)
• In-memory cache (ConcurrentHashMap) for fast lookups
• Manual JSON serialization (no external libs)
• Reflection-based display delegation (avoids circular deps)

**Config**: `PluginV2/src/main/resources/config/party.yml`
```yaml
party:
  max-size: 6
  color: "#00FF00"
  display:
    show-party-prefix: true
    enable-glow: true
  combat:
    disable-friendly-fire: true
    party-buff:
      enabled: true
      damage-boost-per-member: 0.05
```

═══ KNOWN LIMITATIONS ═══

⚠️ **ClusterMessagingService Stubbed**:
• Impact: Cross-server sync uses 5-second database polling
• Mitigation: Acceptable for most use cases, DB as source of truth
• Future: Redis-based ClusterMessagingService for real-time sync

⚠️ **Indirect Damage Sources**:
• Impact: TNT chain reactions, lightning strikes may not be fully blocked
• Mitigation: Direct attacks and projectiles fully protected (most common cases)
• Future: Additional event handlers for EntityExplodeEvent, EntityDamageByBlockEvent
